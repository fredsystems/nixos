# Plan 05: Split sdrhub into adsbhub and corehub

- **Status:** planned
- **Branches:** one `plan05/5.N-*` branch and PR per subtask.

## Goal

Retire sdrhub by moving its two unrelated jobs onto two new mini PCs:

- **adsbhub** runs the SDRs and every ADS-B / ACARS container.
- **corehub** runs the LAN's core services: DNS (AdGuard + Unbound),
  nginx with the `int.fredsystems.org` wildcard, the monitoring master
  (Prometheus, Grafana, Loki and its ruler, Karma, blackbox,
  github-ci-exporter, unbound-exporter), the Tailscale subnet router,
  home-ip-drift, degoog, syncclipboard and the dozzle UI.

All persistent state moves with its service, and history is kept:
Prometheus TSDB, Grafana, Loki, AdGuard, ACME, the ACARS message
databases and the tar1090 / graphs1090 history.

## Decisions

### corehub inherits 192.168.31.20

The address is hardcoded across the fleet: it is the DNS server the
router hands out, every Alloy agent and daytona push to Loki at
`:5678`, daytona remote-writes to Prometheus at `:9090`, and the
AdGuard rewrites answer with it. corehub is built and verified on a
temporary address, then takes `.20` by moving the router's DHCP
reservation at cutover. Only the ADS-B references (nginx proxies,
scrape targets, hfdlhub2's hfdlobserver, the beast-compare feeds) are
repointed, to adsbhub's own address.

The `instance` / `hostname` labels change regardless: new series are
`corehub` and `adsbhub`, old ones keep `sdrhub` until they age out of
retention. Alert rules and their tests that name `sdrhub` are swept by
hand in 5.6 and 5.9, not by find-and-replace.

### The ADSBHub feeder container becomes `adsbhub_feeder`

A container called `adsbhub` on a host called `adsbhub` makes
`docker logs`, cAdvisor and Loki labels ambiguous.

### Provisioning with nixos-anywhere and disko

nixos-anywhere installs a flake configuration over SSH onto a machine
booted from the stock NixOS installer, partitioning with disko. It
replaces the manual flow in `modules/secrets/sops.nix` (clone the repo
on the new machine, run `add_new_system_sop.sh`, re-encrypt, rebuild).

Disks are ext4 with an EFI system partition and swap, matching the
rest of the fleet, and are named by `/dev/disk/by-id`, read off the
live ISO. disko owns `fileSystems` on these two hosts;
`hardware-configuration.nix` is generated by nixos-anywhere with
`--no-filesystems`.

### Secrets work on first boot

sops is not optional even for a bare host: SSH authorized keys come
from sops (`modules/secrets/sops.nix`), so a host without its age key
cannot be logged into. Each host's age key is generated locally, added
to `modules/secrets/.sops.yaml`, and `sops updatekeys` run before the
install. nixos-anywhere places the key at
`/home/fred/.config/sops/age/keys.txt` with `--extra-files` and
`--chown`.

### No GitHub runners on adsbhub

adsbhub does not import `profiles/adsb-hub.nix`, whose runners sdrhub
never had. It imports the same individual modules sdrhub does.

### Disk budget (256 GB each)

Measured on sdrhub 2026-11-14:

| Path                           | Size   | Destination |
| ------------------------------ | ------ | ----------- |
| `/var/lib/prometheus2`         | 77 GB  | corehub     |
| `/var/lib/private/AdGuardHome` | 16 GB  | corehub     |
| `/var/lib/loki`                | 590 MB | corehub     |
| `/var/lib/grafana`             | 95 MB  | corehub     |
| `/opt/adsb/degoog`             | 71 MB  | corehub     |
| `/opt/adsb/syncclipboard`      | 16 MB  | corehub     |
| `/opt/adsb/data`               | 17 GB  | adsbhub     |
| `/opt/adsb/backups`            | 9.1 GB | adsbhub     |

corehub carries about 95 GB of state on a 256 GB disk, before the Nix
store. The Prometheus snapshots under `data/snapshots` are hard links
to TSDB blocks, so every copy uses `rsync -aHAX`: without `-H` they
are duplicated and the copy no longer fits. The rest of `/opt/adsb`
(`docker-back`, `postgres-data`, `docker-compose.yaml`, ...) is
leftover from the compose era and does not move.

### Copies map ownership by name

`prometheus` and `grafana` have static UIDs in nixpkgs; `loki` and
AdGuard's DynamicUser do not. Each destination runs its full
configuration once before the copy, so the service users exist, and
`rsync` runs without `--numeric-ids` so ownership maps by name.

## Execution model

Strictly sequential: each phase cuts over live services the next one
depends on. One branch and PR per subtask, merged in order, and every
host is deployed from the merged commit on `main`, so the running
generation is the one CI cached and `fleet-manifest.yaml` records.

Plan 02 is in progress and its 2.12 baseline records on sdrhub's SDRs.
5.5 moves those SDRs, which is a setup change under Plan 02 (new
`runId`). Whether 2.12 finishes first, and whether this plan may
complete ahead of Plan 02 as Plans 03 and 04 did, is the owner's call
and is recorded here when made.

## Subtasks

### Phase 0: prep (before the hardware)

- [ ] **5.1 disko and nixos-anywhere.** Add the `disko` flake input,
      wired by the builder for nodes that declare a disk layout, and
      `nixos-anywhere` to the dev shell.
- [ ] **5.2 Host scaffolds.** `hosts/linux/{adsbhub,corehub}/` with a
      base-only `configuration.nix` (hostname, sops, nothing else) and
      `disk-config.nix`; node entries in `flake/hosts/servers.nix`
      (`stateVersion = "26.05"`, literal `targetHost` until mDNS
      resolves, as nvrhub did). Generate both age keys, add them to
      `.sops.yaml`, `sops updatekeys`. The disk `by-id` paths are
      filled in from the live ISO in 5.3.

### Phase 1: bare install

- [ ] **5.3 Install both hosts.** For each: boot the NixOS minimal ISO,
      `passwd`, note the address and `ls -l /dev/disk/by-id`. Set the
      disk path, then from daytona:

      ```sh
      nixos-anywhere --flake .#<host> \
        --generate-hardware-config nixos-generate-config \
          hosts/linux/<host>/hardware-configuration.nix \
        --extra-files <dir holding home/fred/.config/sops/age/keys.txt> \
        --chown /home/fred/.config 1000:100 \
        --target-host nixos@<address>
      ```

      This wipes the target disk. Commit the generated hardware
      configs, set DHCP reservations (adsbhub permanent, corehub
      temporary), and confirm `colmena apply --on <host>` works.

### Phase 2: ADS-B and ACARS to adsbhub

- [ ] **5.4 adsbhub configuration.** Move from sdrhub: every container
      except degoog, syncclipboard and the dozzle UI (dozzle-agent goes
      to both); beast-compare, sqliteBackup and backupFreshness for the
      ACARS databases; usbfs; their sops secrets. Rename the feeder
      container to `adsbhub_feeder`. Check the
      `/sys/class/thermal/thermal_zone2` mounts against the new
      hardware. Add the monitoring agent. Deployed with the containers
      stopped (not yet enabled) until 5.5.
- [ ] **5.5 ADS-B cutover.** Stop the containers on sdrhub first, so
      the feeder keys and MLAT identity never run twice. `rsync -aHAX`
      `/opt/adsb/data` and `/opt/adsb/backups`; the acarshub databases
      are WAL-mode and are only copied stopped. Move the SDRs (a powered
      USB hub may be needed for Airspy, two RTL-SDRs and the LNA).
      Enable on adsbhub and, in the same PR, repoint sdrhub's nginx
      proxies, the Prometheus scrape targets, hfdlhub2's
      `settings.yaml`, vdlmhub's ZMQ consumer and the
      `flake/dev/checks.nix` decoder-unit check. Repoint the NAS's
      nightly `/opt/adsb` pull by hand (it is configured on the NAS).

### Phase 3: everything else to corehub

- [ ] **5.6 corehub configuration.** Move the rest of sdrhub's
      configuration: DNS with `deployment.criticalUnits`, nginx and
      `acme.nix`, the landing page, the monitoring master, home-ip-drift,
      Tailscale with `--advertise-routes`, degoog, syncclipboard and the
      dozzle UI. Deploy once at the temporary address so the service
      users exist, then stop the stateful services. Verify DNS with
      `dig @<temporary address>`.
- [ ] **5.7 Core cutover.** Stop the services on sdrhub. `rsync -aHAX`
      `/var/lib/prometheus2`, `/var/lib/grafana`, `/var/lib/loki`,
      `/var/lib/private/AdGuardHome`, `/var/lib/acme`,
      `/opt/adsb/degoog` and `/opt/adsb/syncclipboard`. Move the `.20`
      reservation to corehub, reboot it, verify. LAN DNS is down for
      the window; point the router's secondary DNS at 1.1.1.1 for it if
      that matters. Re-approve the subnet route in the Tailscale admin
      console.

### Phase 4: retire sdrhub

- [ ] **5.8 Remove sdrhub.** Remove it from `servers.nix`,
      `sync-hosts.nix`, `lanHosts` and the test fixtures; sweep the
      remaining `sdrhub` references and alert tests. Revoke its sops
      recipient (`updatekeys` and `sops rotate`, per
      `agent-docs/SOPS_AGE_KEY_ROTATION.md`). Remove it from the
      tailnet, then wipe it.
- [ ] **5.9 Secret and label cleanup.** Rename `docker/sdrhub/*`
      secrets to the hosts that consume them; finish the alert-rule
      label sweep.
- [ ] **5.10 Cache.** CI builds and pushes every host whose closure
      changed, and new hosts always qualify, so deploying from `main`
      is what keeps Attic current. As a final check, from the deployed
      commit:

      ```sh
      nix build .#nixosConfigurations.{adsbhub,corehub}.config.system.build.toplevel
      scripts/attic-push.sh result result-1
      ```

      and confirm each host's `/run/current-system` matches the fleet
      manifest.
